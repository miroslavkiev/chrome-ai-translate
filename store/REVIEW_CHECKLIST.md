# Chrome Web Store review checklist

Draft, checked September 6, 2026. This is a release checklist, not a statement that the extension meets every policy. Recheck the linked sources at submission time. Publisher decisions and legal questions are tracked in [LEGAL_REVIEW.md](LEGAL_REVIEW.md).

## Prepared locally

- [x] Manifest V3, packaged scripts, local icons, and no downloaded code execution. Gemini returns text and model data; the extension does not execute it. The dashboard remote-code answer can be **No**. [Chrome remote-code declaration](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy).
- [x] Network host permission is limited to `https://generativelanguage.googleapis.com/*`. Declarative content scripts still cover HTTP, HTTPS, and approved local files for the Control-key feature. The existing browser checks passed with this narrower permission, including file access on/off and embedded frames. Broad page access still needs a clear explanation. [Chrome permissions](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions).
- [x] Public project, support, and privacy links are present. The updated privacy text describes encrypted key storage, automatic use, the browser-profile access limit and the data agreement. It does not claim OS keychain protection or legal clearance.
- [x] The approved purple icon, plain feature description, Mac-only manual-testing note, and AI accuracy note are included.
- [x] No real credentials were found in the audit through commit `c81bd6e`: 21 commits, 182 unique file blobs, and 14 ZIP versions. This is evidence for that snapshot, not a guarantee about later edits or external copies.

## Final checks and recorded publication risks

- [x] **Verify the selected key storage.** The publisher selected option D: AES-256-GCM with a nonextractable encryption key in IndexedDB, for automatic use after restart. Both are kept in the same profile, so profile access remains a limit. Test full restart, legacy migration, damaged storage, removal and stale Settings tabs. Verify decryption before deleting legacy plain text copies; failed migration must retain the old key and block requests. Remove saved key must delete ciphertext, encryption key and model cache, retaining only the non-secret revision marker. Record final evidence in [RELEASE_CHECKS.md](../RELEASE_CHECKS.md). AES is named in Chrome's secure-handling FAQ, but using it alone does not establish approval. [Selected design](KEY_STORAGE_OPTIONS.md), [Chrome data FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq).
- [x] **Verify informed disclosure and the agreeing action.** The chosen button is Agree and connect to Google. Before agreement, no Google request may start, including with a migrated key or cached models. Verify local agreement version/date storage across restart, persistent review text, withdrawal during active work and agreement again after withdrawal. Withdrawal keeps the encrypted key and preferences but blocks future requests. A link alone is not completed consent, and the agreement cannot recall data already sent. [Chrome disclosure guidance](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq).
- [ ] **Check the use notice and distribution settings.** The publisher chose acceptance through use, without a separate eligibility checkbox or identity checks. The in-app notice and [draft description](LISTING.md) state the adult, work/business, supported-region and worldwide active-billing conditions, plus the ban on optional contribution of extension request data to Google. Choose supported Store distribution countries and ensure the actual offering matches the app-level restrictions. A valid key, successful model check or notice does not prove eligibility or remove the developer's own duties. Google does not expressly require an eligibility checkbox in the reviewed clauses. [Gemini terms](https://ai.google.dev/gemini-api/terms), [Google API Terms section 2(a)](https://developers.google.com/terms#section_2_using_our_apis).
- [x] **Set the required data-use arrangement and publish the Limited Use commitment.** The extension now requires active billing in every country and forbids optional contribution of its request logs or datasets to Google for product improvement or training, including feedback that shares this data. Private project logging remains separate. Unpaid projects are outside supported use. The public privacy page includes an affirmative Limited Use commitment for that setup. Paid-service terms exclude product improvement but retain limited security and legal handling. The extension does not verify Google project settings; the final dashboard certification is scheduled for submission and is not a claim of approval. [Gemini data-use terms](https://ai.google.dev/gemini-api/terms), [Google sharing policy](https://ai.google.dev/gemini-api/docs/logs-policy), [Chrome Limited Use](https://developer.chrome.com/docs/webstore/program-policies/limited-use).
- [ ] **Record publisher information limits and check public pages.** The publisher explicitly chose not to provide a public postal address. No address or contact details may be inferred. If an address is required, omission remains a publication risk; it does not block approved local work or require the same question again. Applicable privacy contact information remains unresolved, and the legal-notice template stays unused. Verify that support and privacy URLs work without signing in and that the dashboard matches the final package. [Legal review](LEGAL_REVIEW.md), [Store privacy fields](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy).
- [ ] **Review the requested donation link.** It is optional and opens the foundation's site; the extension does not collect payments. The destination funds military equipment. Chrome prohibits facilitating regulated-product sales and may limit featuring for political content. No explicit blanket ban on this optional donation link was found, so approval remains uncertain. Keep the requested link unless the publisher chooses otherwise; do not claim that it is approved. [Foundation destination](https://www.sternenkofund.org/en/donate), [Chrome content and featuring policies](https://developer.chrome.com/docs/webstore/program-policies/policies).

## Draft dashboard data categories

These are conservative recommendations based on the current runtime, not completed dashboard answers. Local handling also counts. No analytics does not mean no user data. Reconcile the final answers with the selected-content scope, provider terms, public privacy text, and any new storage flow. [Chrome data handling FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq).

| Dashboard category | Draft treatment | Actual scope |
| --- | --- | --- |
| Authentication information | Yes | The user's API key is stored and sent to Google for models and translation. No Google password or account cookie is requested. |
| Website content | Yes | Selected text and generated translations are handled. This includes enabled local-file pages. Whole pages are not uploaded. |
| User activity | Yes, conservatively | Keyboard, pointer, selection, and page events are processed locally to start or cancel the trigger and position results. Recent request timestamps and the latest result time are kept for the session. There is no keystroke history, click analytics, or event stream sent to the developer. The chosen shortcut itself can sync as a preference. |
| Web history | Yes, conservatively, with a narrow explanation | Chrome supplies the current page/frame URL and origin for sender validation and request identity. There is no history API access, list of visited pages, or page URL added to the Gemini payload. |
| Personal communications | Review selected-content scope; do not assume No | A user can select text in a message or email and send it for translation. There is no separate mailbox access or message scraping. |
| Personally identifiable information | Review selected-content scope; do not assume No | Names, contact details, and other identifiers can be present in selected text. There is no separate profile or registration form. Public support issues are a separate channel and must not request private data. |
| Financial and payment information | Review selected-content scope; do not assume No | Such information can be present in selected text. The extension has no billing form and does not process the optional donation. |
| Health information | Review selected-content scope; do not assume No | Such information can be present in selected text. There is no separate health-data access or medical feature. |
| Location | Review selected-content and provider metadata | A selected passage can contain an address. Google receives normal connection information such as the source IP address. The extension does not use geolocation or add location fields to its translation request. |

The unresolved rows cannot be changed to No just because the content was chosen by the user. Before submission, confirm how the dashboard categories apply to unrestricted selected text, or narrow the supported use with effective controls. Do not describe incidental content as a separate feature that the extension does not have. Google's paid-service terms also describe IP addresses and other operational metadata. [Gemini terms](https://ai.google.dev/gemini-api/terms).
