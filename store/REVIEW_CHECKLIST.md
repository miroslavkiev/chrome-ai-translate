# Chrome Web Store review checklist

Draft, checked September 5, 2026. This is a release checklist, not a statement that the extension meets every policy. Recheck the linked sources at submission time. Publisher and legal questions are tracked in [LEGAL_REVIEW.md](LEGAL_REVIEW.md).

## Prepared locally

- [x] Manifest V3, packaged scripts, local icons, and no downloaded code execution. Gemini returns text and model data; the extension does not execute it. The dashboard remote-code answer can be **No**. [Chrome remote-code declaration](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy).
- [x] Network host permission is limited to `https://generativelanguage.googleapis.com/*`. Declarative content scripts still cover HTTP, HTTPS, and approved local files for the Control-key feature. The existing browser checks passed with this narrower permission, including file access on/off and embedded frames. Broad page access still needs a clear explanation. [Chrome permissions](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions).
- [x] Public project, support, and privacy links are present. The privacy text describes current storage and transfer behavior. It does not claim that persistent API keys are encrypted.
- [x] The approved purple icon, plain feature description, Mac-only manual-testing note, and AI accuracy note are included.
- [x] No real credentials were found in the audit through commit `c81bd6e`: 21 commits, 182 unique file blobs, and 14 ZIP versions. This is evidence for that snapshot, not a guarantee about later edits or external copies.

## Still blocking submission

- [ ] **Protect the saved key.** The current key is stored without encryption in `chrome.storage.local`. Trusted-context access does not encrypt it. Chrome's FAQ calls for strong encryption at rest. The first three proposals were session-only, passphrase-encrypted persistence, and entry for each translation. A fourth proposal uses AES-GCM with a nonextractable key in IndexedDB for automatic use after restart, with a clear browser-profile access limit. It passed an isolated restart proof but has not been selected or implemented, and does not establish Store approval. Review [KEY_STORAGE_OPTIONS.md](KEY_STORAGE_OPTIONS.md), choose the flow, and test its implementation. Any password-based option must keep its unlock password out of persistent browser storage. [Chrome data FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq), [memory-only session storage](https://developer.chrome.com/docs/extensions/reference/api/storage).
- [ ] **Finish informed disclosure and the agreeing action.** The key is sent to Google for model discovery as soon as it is saved. Selected text is sent for translation. The new text before key entry explains this, but the final storage and consent flow is not yet chosen. A link alone must not be treated as completed consent. [Chrome disclosure guidance](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq).
- [ ] **Finish the use notice and distribution settings.** The publisher chose a notice with acceptance through use, without a separate eligibility checkbox or identity checks. [The draft description](LISTING.md) now states the adult, work/business, supported-region and active-billing conditions. Show them before first API use, choose supported Store distribution countries, and ensure the actual offering matches the app-level restrictions. A valid key, successful model check or notice does not prove eligibility or remove the developer's own duties. Google does not expressly require an eligibility checkbox in the reviewed clauses. [Gemini terms](https://ai.google.dev/gemini-api/terms), [Google API Terms section 2(a)](https://developers.google.com/terms#section_2_using_our_apis).
- [ ] **Resolve Limited Use before certifying it.** Some unpaid Gemini use permits product improvement and human review. Paid-service terms exclude product improvement but retain limited safety and legal logging. Confirm the chosen provider arrangement meets Chrome's permitted uses and human-access limits. Then add an accurate affirmative Limited Use statement to the public privacy page and complete the dashboard certification. Do not tick the certification now merely because the developer has no backend. [Gemini data-use terms](https://ai.google.dev/gemini-api/terms), [Chrome Limited Use](https://developer.chrome.com/docs/webstore/program-policies/policies#limited-use).
- [ ] **Finish publisher details and public pages.** Resolve the applicable items in [LEGAL_REVIEW.md](LEGAL_REVIEW.md). Verify that support and privacy URLs work without signing in and that the dashboard matches the final package. [Store privacy fields](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy).
- [ ] **Review the requested donation link.** It is optional and opens the foundation's site; the extension does not collect payments. The destination funds military equipment. Chrome prohibits facilitating regulated-product sales and may limit featuring for political content. No explicit blanket ban on this optional donation link was found, so approval remains uncertain. Keep the requested link unless the publisher chooses otherwise; do not claim that it is approved. [Foundation destination](https://www.sternenkofund.org/en/donate), [Chrome content and featuring policies](https://developer.chrome.com/docs/webstore/program-policies/policies).

## Draft dashboard data categories

These are conservative recommendations based on the current runtime, not completed dashboard answers. Local handling also counts. No analytics does not mean no user data. Reconcile the final answers with the selected-content scope, provider terms, public privacy text, and any new storage flow. [Chrome data handling FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq).

| Dashboard category | Draft treatment | Actual scope |
| --- | --- | --- |
| Authentication information | Yes | The user's API key is stored and sent to Google for models and translation. No Google password or account cookie is requested. |
| Website content | Yes | Selected text and generated translations are handled. This includes enabled local-file pages. Whole pages are not uploaded. |
| User activity | Yes, conservatively | Keyboard, pointer, selection, and page events are processed locally to start or cancel the trigger and position results. Recent request timestamps and the latest result time are kept for the session. There is no keystroke history, click analytics, or event stream sent to the developer. The chosen shortcut itself can sync as a preference. |
| Web history | Yes, conservatively, with a narrow explanation | Chrome supplies the current page/frame URL and origin for sender validation and request identity. There is no history API access, list of visited pages, or page URL added to the Gemini payload. |
| Personal communications | Review selected-content scope; do not assume No | A user can select text in a message or email and send it for translation. There is no separate mailbox access or message scraping. |
| Personally identifiable information | Review selected-content scope; do not assume No | Names, contact details, and other identifiers can be present in selected text. There is no separate profile or registration form. Public support issues are a separate channel and must not request private data. |
| Financial and payment information | Review selected-content scope; do not assume No | Such information can be present in selected text. The extension has no billing form and does not process the optional donation. |
| Health information | Review selected-content scope; do not assume No | Such information can be present in selected text. There is no separate health-data access or medical feature. |
| Location | Review selected-content and provider metadata | A selected passage can contain an address. Google receives normal connection information such as the source IP address. The extension does not use geolocation or add location fields to its translation request. |

The unresolved rows cannot be changed to No just because the content was chosen by the user. Before submission, confirm how the dashboard categories apply to unrestricted selected text, or narrow the supported use with effective controls. Do not describe incidental content as a separate feature that the extension does not have. Google's paid-service terms also describe IP addresses and other operational metadata. [Gemini terms](https://ai.google.dev/gemini-api/terms).

## Final package and listing checks

- [x] Run the source, unit, browser, and package checks against the final changed build. Confirm the ZIP has `manifest.json` at its root, all declared resources, and a matching version/checksum.
- [x] Confirm the Store icon is a 128x128 PNG; use the 96x96 square-artwork guide with transparent space around it. Manifest SVG and WebP icons are unsupported. [Store image guide](https://developer.chrome.com/docs/webstore/images), [manifest icon formats](https://developer.chrome.com/docs/extensions/reference/manifest/icons).
- [x] Supply a 440x280 promotional image and at least one screenshot at 1280x800 or 640x400. The 1400x560 marquee image is optional. Screenshots must show real functionality; label example text and translations. The smaller images embedded in Help are not listing screenshots. [Store image guide](https://developer.chrome.com/docs/webstore/images).
- [x] Check every public image for real keys, account details, project names, and hidden text metadata. Re-run redacted secret scanning on the final working tree, new Git objects, and final ZIP.
- [x] Verify the listing states the own-key requirement, possible Google charges, supported pages, and the manual-testing limit. Keep claims consistent with the build. [Store listing guidance](https://developer.chrome.com/docs/webstore/cws-dashboard-listing).
- [x] Give reviewers a clear setup and test route. The private Test instructions field can hold restricted review details if needed; never put a working key in the package, public repository, listing, or screenshots. That field is optional, not proof of approval. [Reviewer test instructions](https://developer.chrome.com/docs/webstore/cws-dashboard-test-instructions).
- [ ] Confirm the developer account, required contact details, two-step verification, distribution regions, and final privacy answers before submitting. A passing build or an uploaded ZIP is not a Store approval. [Publishing guide](https://developer.chrome.com/docs/webstore/publish/).
