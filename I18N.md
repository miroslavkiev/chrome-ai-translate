# Interface languages

The extension covers the 55 locales listed in Chrome's [i18n documentation](https://developer.chrome.com/docs/extensions/reference/api/i18n), checked September 6, 2026. This includes regional variants. The Norwegian catalog uses the native browser code `nb`, while the Store table calls it `no`. Real Chrome 140 and 151 checks confirmed that a `no` folder alone falls back to English. These interface locales are separate from the 110 Gemini translation targets, which keep `no` for Norwegian.

Chrome selects the interface language. On macOS, Chrome uses the system language setting. English is the fallback for a missing or unsupported interface language. A catalog metadata message identifies the language actually displayed, so an Urdu Chrome interface gets correctly marked English text with left-to-right layout. Settings, the toolbar popup, translation cards, context menu, Help, About, accessibility labels and errors use packaged translations. No translation service runs to translate the interface.

For new setup, the target-language suggestion follows Chrome's preferred languages in order. It chooses the first supported target, then the interface language, then English. Regional tags map to their language, with Simplified and Traditional Chinese kept separate. The user confirms or changes the suggestion with Finish setup. Saved choices, including settings from earlier versions, are preserved.

## Updating translations

1. Edit the English message in `_locales/en/messages.json` and every supported locale. Keep message IDs stable. The `ui_locale` metadata message must match its folder in BCP 47 form, for example `pt-BR`.
2. Preserve named `$PLACEHOLDER$` references and their definitions. Preserve paired numbered tags such as `<1>text</1>`; these wrap existing trusted links or emphasis. Never add HTML to a message.
3. Keep the extension name within 75 characters and its description within 132 characters.
4. Run `npm run ci`. The package checks require all 55 catalogs, identical message IDs and placeholders, balanced matching tags, and exact package contents.
5. Run `npm run test:browser`. Native locale checks cover English, the Australian English mapping, German, Arabic, Japanese, Norwegian, Ukrainian and Simplified Chinese, including setup, the refresh dialog, narrow layouts, saved preferences and the English fallback under an Urdu Chrome interface. `I18N_TEST_LOCALES=fr,he` selects another set for the locale check script.

Browser checks use disposable profiles, fake keys and fake provider replies. On macOS, a process-only Apple language option selects actual Chrome catalogs and the mock-keychain launch flag prevents test-browser keychain prompts. The tests do not change the user's system or browser language. Worker discovery can wake an already registered worker after a late test attachment; missing or failed registration remains a bounded failure.

## Chrome guide review

The implementation follows the [Concepts and usage guide](https://developer.chrome.com/docs/extensions/reference/api/i18n#concepts_and_usage):

| Chrome guidance | Implementation |
| --- | --- |
| Native locale folders | `_locales/<locale>/messages.json`, checked against Chrome's 55 codes. |
| Required default locale | Manifest `default_locale` is `en`. |
| Manifest messages | Name and summary use `__MSG_...__`. |
| JavaScript messages | Shared `t()` calls `chrome.i18n.getMessage()`. |
| Native fallback order | Chrome chooses regional, base and default messages. |
| Placeholders | Named placeholders keep dynamic values outside translated sentences. |
| Direction | Native `@@bidi_dir` and logical CSS support RTL; English fallback uses LTR. |
| Separate language APIs | Chrome selects the message catalog; `getAcceptLanguages()` supplies target suggestions, with raw `getUILanguage()` as fallback. |
| Safe output | Text nodes preserve trusted links without interpreting translations as HTML. |

The maximum substitution count used here is two, below Chrome's limit of nine. Locale examples and metadata do not contain real keys or account details. The preferred-language API does not say whether a user edited its list manually.

The source-folder and packaged installs both use the bundled background script. Chrome does not support native worker import assertions; a restart check caught this limit, so JSON catalogs are bundled before worker loading. The right-click menu refreshes its language on browser startup.
